# Game data

Game data files, embedded into `crafting-core` at build time with `include_str!`
(see `docs/adr/0008-game-data-files.md`). Nothing is read from disk or the network at runtime.

## Source and provenance of base_items.json and mods.json

`base_items.json` and `mods.json` are generated by the converter `data-import` from the RePoE
export for Path of Exile 1 (ADR 0015, ADR 0016). Do not edit them by hand.

- Source: RePoE, export for Path of Exile 1, https://repoe-fork.github.io/ (export page
  https://repoe-fork.github.io/poe1.html). The raw files are not in the repository.
- Game version: 3.29.3.3, as stated on the export page; the files do not carry a version.
- Download date of the raw files: 2026-10-25.
- Converted bases: the 31 ring bases that the PO selected (ADR 0017), listed in
  `data-import/src/main.rs`: item class Ring and release state `released` in RePoE, without the
  four Royale variants (`RingRoyale1` to `RingRoyale4`), the six Breach rings (Cryonic,
  Enthalpic, Formless, Fugitive, Organic and Synaptic Ring), the six Heist rings (Cogwork,
  Composite, Geodesic, Ratcheting, Helical and Manifold Ring), Golden Hoop and Jet Ring. The
  "Breach Ring" (`BreachRing`) and the base "Ring" (`MirrorRing`) are included. Two-Stone Ring
  and Shadowed Ring occur three times each with different implicits; they are separate bases
  with separate identifiers.
- Command, with the directory of the six raw files as argument (it overwrites both data files;
  on an error it prints the message and writes nothing):

  ```
  cargo run -p data-import -- <directory of the raw files>
  ```

A data change is a converter run with new raw files and an updated provenance section in the
same commit. The same raw files give byte-identical data files.

Values are stored as RePoE has them, including values no function uses yet: stat identifiers
with underscores, tags in lower case, raw stat ranges. Texts come from the English entries of
`stat_translations.json`, in the order of the game. Reminder texts are not imported.

## base_items.json

```
{ "base_items": [ BaseItem, ... ] }
```

BaseItem:
- `id`: item identifier, e.g. `Metadata/Items/Rings/Ring1`
- `name`: item name (English original)
- `item_class`: name of the item class (English original), e.g. `Rings`
- `required_level`: the level requirement of the base item itself (`requirements.level` in
  RePoE), 0 if it has none (rings). The requirement an item shows is computed from this and the
  levels of its mods (`poe-crafting-rules`).
- `tags`: tags of the base
- `implicits`: list of mods the base item always has
- `mod_pool`: identifiers (`id` in `mods.json`) of the prefixes and suffixes that can roll on the
  base: the categories `prefix` and `suffix` of its entry in `mods_by_base.json` (ADR 0016), in
  the order of `mods.json`. Each base has its own pool (ADR 0017): 28 bases have the 207 mods of
  the Iron Ring, Bone Ring and Gloam Ring have 23 minion mods more, the Unset Ring 3 mods for
  socketed gems. `crafting-core` offers the pool of a base as `mod_pool(base_id)`.

Mod (an implicit):
- `family`: the mod's group
- `level`: level of the mod (`required_level` in RePoE)
- `tags`: mod tags (`implicit_tags` in RePoE)
- `stats`: one or more stats `{ "id", "min", "max" }`. `id` is the stat identifier of RePoE;
  `min`/`max` is the raw range the stat rolls in.
- `text`: display text with named placeholders, e.g. `Adds {attack_minimum_added_physical_damage}
  to {attack_maximum_added_physical_damage} ...`. A text with several lines separates them with
  `\n`, in the order of the game. A stat whose text shows no value (RePoE format `ignore`, e.g.
  "Has 1 Socket" of the Unset Ring) stays in `stats`, but no placeholder names it.
- `placeholders`: maps each placeholder name in `text` to the identifier of a stat of the same
  mod (the converter names each placeholder after its stat). The text is rendered through the
  identifier, never through the order of the stats.
- `conversions`: maps the identifier of a stat that the game converts for display to
  `{ "divisor": n, "precision": n or null }`: the shown value is the raw value divided by
  `divisor`, rounded to `precision` decimals; without a precision it is exact
  (`poe-crafting-rules`, "Item basics"). The divisor is a whole number that is never zero. A
  negative divisor reverses the sign: `-1` is RePoE's handler `negate` (a raw -15 is shown as
  15, in the wording of the game "15% reduced ..."; ADR 0017). A stat that is not in the map is
  shown as rolled.

## item_slots.json

Written by hand (ADR 0018). It assigns item classes to equipment slots, so that no item class
name is written into code.

```
{ "slots": [ { "id": "ring", "item_classes": ["Rings"] }, ... ] }
```

- `id`: the identifier of a slot (`Slot::id` in `crafting-core`: `weapon`, `helmet`, `off_hand`,
  `body_armour`, `amulet`, `ring`, `belt`, `gloves`, `boots`); listed at most once. A slot
  without an entry has no item classes and is not available.
- `item_classes`: names of item classes as in the `item_class` field of `base_items.json`. A class
  belongs to one slot only, and some base must have it.

Every base's item class must belong to a slot. Loading the data stops with an error when the
file breaks one of these rules. A story that imports bases of a new item class adds the class here.

Loading the data also stops when the implicit of a base has a range that `poe-crafting-rules`
does not define (a range of a converted or negative value), because the list of bases shows the
implicit texts with ranges (`ModDefinition::range_text`).

## mods.json

```
{ "mods": [ ExplicitMod, ... ] }
```

ExplicitMod has the fields of a Mod (see above) and:
- `id`: the RePoE mod identifier, e.g. `IncreasedLife0`
- `name`: name of the mod, used in the item name (`Hale` before the base name,
  `of the Pupil` after it); unique
- `affix_type`: `prefix` or `suffix`
- `weight`: spawn weight in the pool, greater than zero

The file holds every mod that is in the pool of a base item of `base_items.json`, sorted by
affix type (prefixes first), family, level and identifier.

## currencies.json

Source: names from the story texts of AB#62 and AB#114 (ADR 0011); descriptions and failure
messages from the story texts of AB#113 and AB#114 (ADR 0012).

```
{ "currencies": [ { "id": "...", "name": "...", "description": "...", "messages": { ... } }, ... ] }
```

- `id`: project identifier in lower snake case, not a game value; unique
- `name`: English name of the currency (game text, shown unchanged)
- `description`: the currency's English game description (game text, shown unchanged)
- `messages`: maps a reason code to the game's failure message for this currency (game text,
  shown unchanged). The keys are the codes of `CraftError` (`item_not_normal`,
  `item_not_magic`, `no_valid_mod`); a currency has a message for every reason it can fail
  with, and for no other.
